# Standalone EE/CSEP VLM Evaluation

This folder is a self-contained evaluator for only two metrics:

- `EE_v3`: VLM-as-judge edit effectiveness.
- `CSEP_v3`: VLM-as-judge cross-shot edit consistency.

It is intentionally independent from the rest of the repository. It does not
import `mseditbench`. After cloning this folder, a user only needs to provide:

1. Ark API credentials.
2. Source videos.
3. Edited videos generated by one or more models.

The prompt JSON files under `prompts/` are copied from
`runs/edit_prompts_v3_vlm/T*.json`.


## Install

Use Python 3.10+.

```bash
cd standalone_ee_csep_eval
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

If you already have a working environment with `numpy`, `opencv-python`,
`tqdm`, and `volcenginesdkarkruntime`, you can use that environment directly.

## API Setup

Copy `.env.example` and fill in your key:

```bash
cp .env.example .env
source .env
```

The API call follows the same Ark client style as `seedance_api_example`:

```python
from volcenginesdkarkruntime import Ark

client = Ark(
    base_url="https://ark.cn-beijing.volces.com/api/v3",
    api_key=os.environ["ARK_API_KEY"],
)
```

Default VLM model:

```text
doubao-seed-2-0-lite-260215
```

Override it with:

```bash
export VLM_MODEL_ID="your-model-id"
```

Put edited model outputs under `video_results/<MODEL_NAME>/videos/<TASK>/`:

```text
video_results/
  seedance_fast/

      T2/

      T9/
        00000_T9_0000_k0.mp4

    videos/
      T1/
```

The evaluator also accepts these looser layouts:

```text
video_results/<MODEL_NAME>/<TASK>/<sample_id>_k0.mp4
video_results/<MODEL_NAME>/videos/<sample_id>_k0.mp4
video_results/<MODEL_NAME>/<sample_id>_k0.mp4
```

## Run

Evaluate all tasks and all model folders under `video_results/`:

```bash
python src/eval_ee_csep.py
```

Evaluate selected tasks:

```bash
python src/eval_ee_csep.py --tasks T1,T2,T9
```

Evaluate selected models:

```bash
python src/eval_ee_csep.py --models seedance_fast,seedance_pro
```

Quick smoke test on the first two prompts of T1:

```bash
python src/eval_ee_csep.py --tasks T1 --limit 2
```

Useful runtime parameters:

```bash
python src/eval_ee_csep.py \
  --tasks all \
  --k 0 \
  --stride 4 \
  --max_frames_per_shot 6 \
  --ee_frame_pairs_per_shot 3
```

Outputs are written to:

```text
outputs/
  summary.csv
  summary.md
  MODEL_NAME/
    T1/
      aggregate.json
      00000_T1_0000_k0.eval.json
```

## Metric Behavior

### EE_v3

For each edit unit, the evaluator:

1. Uses only the shots listed in `applicable_shots`.
2. Slices source and edited videos by the prompt JSON shot boundaries.
3. Samples matched source/edit frame pairs at the same relative positions.
4. Sends one source image and one edited image to the VLM with `vlm_prompts/ee_v3.txt`.
5. Averages frame-pair scores into a shot score, then averages shot scores into the edit-unit score.

T6 prompts contain `[EDIT]` and `[KEEP]` lines. The evaluator strips all
`[KEEP]` lines and sends only the direct `[EDIT]` instruction for the edited
shot to the VLM.

T9 is split into separate edit units:

- `independent_per_shot`: one edit unit per edited shot; CSEP is skipped.
- `sequential_two_edit_prompt`: edit A and edit B are evaluated separately.
  If the same shot contains both edits, that shot is scored once for edit A
  and once for edit B with different VLM prompts.

### CSEP_v3

For each edit unit with at least two applicable shots, the evaluator:

1. Takes every pair of applicable edited shots.
2. Sends two edited frame sets to the VLM with `vlm_prompts/csep_v3.txt`.
3. Averages all pairwise consistency scores.
4. Combines consistency with EE coverage:

```text
CSEP_v3 = sqrt(coverage * consistency)
```

Image count per CSEP VLM call:

- Each call compares two edited shots: `FRAME-SET A` and `FRAME-SET B`.
- By default, each frame set contains 2 images.
- Therefore one CSEP call sends 4 images total by default.
- Override with `VLM_FRAME_SET_IMAGES`.
- If a shot has fewer available sampled frames, the evaluator sends the available count.

If an edit unit has `m` applicable shots, CSEP makes `m choose 2` VLM calls.

### T5

T5 shot-reorder prompts are skipped for EE/CSEP because the current metric
definition scores edit effectiveness on original applicable shots, while T5
changes the temporal shot order.

## Prompt Templates

The VLM text prompts are stored in:

```text
vlm_prompts/ee_v3.txt
vlm_prompts/csep_v3.txt
```

They intentionally do not expose internal benchmark metadata such as
`task_id`, `edit_type`, `source_task`, or `shot_id`. The VLM only sees:

- images or frame sets;
- the direct edit instruction;
- the scoring rubric.

## OmniShotCut Utility

The EE/CSEP evaluator above follows the current benchmark behavior and slices
source/edit videos by the prompt JSON shot boundaries. It does not require
shot detection.

For standalone shot-boundary inspection, this folder includes a minimal
OmniShotCut wrapper:

```text
src/omnishotcut_minimal.py
```

Expected local paths:

```text
third_party/OmniShotCut/
checkpoints/OmniShotCut_ckpt.pth
```

Run:

```bash
python src/omnishotcut_minimal.py \
  --video video_results/seedance_fast/videos/T1/00000_T1_0000_k0.mp4 \
  --output_json outputs/shotcuts/00000_T1_0000_k0.shots.json
```

Default parameters match the main benchmark:

```text
clean_shot=True
num_context_frames=20
```

Use `--include_transitions` only if you want OmniShotCut transition ranges as
well as hard/general cuts.

## Notes

- The evaluator stores raw VLM responses in each per-sample JSON for auditing.
- API failures for an individual frame pair or shot pair are recorded as zero
  for that call and preserved in the JSON.
- This folder is designed for Git push as a standalone evaluation kit. Large
  source videos, edited results, model checkpoints, and third-party code should
  normally be provided by users after clone.
